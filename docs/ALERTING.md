# 告警、通知渠道与投递

管理员配置渠道和规则；管理员与 operator 可确认告警；viewer 只读告警。所有配置变更、测试、确认和手动重试写入操作审计。

## 六种通知方式

| 类型 | 必填配置 | 说明 |
|---|---|---|
| 企业微信 | 群机器人 HTTPS Webhook 地址 | 校验响应 errcode；按渠道最多约 20 次/分钟 |
| 钉钉 | HTTPS Webhook；启用加签时填签名密钥 | 自动生成毫秒时间戳和 HMAC 签名；机器人安全关键词须包含实际消息中的文字 |
| 飞书 | HTTPS Webhook；启用加签时填签名密钥 | 自动生成秒级时间戳与签名 |
| Telegram | Bot Token、Chat ID | 固定官方 Bot API；Bot 需要接收群/用户的发送权限 |
| SMTP | 主机、端口、TLS 模式、发件人、收件人 | 支持隐式 TLS 和 STARTTLS；需要登录时填写用户名/密码，不支持明文连接 |
| Webhook | HTTPS 地址，可选签名密钥 | POST JSON：id、title、text、at；2xx 视为接收成功 |

在「通知渠道」保存，再点「发送测试」。测试会进入真实投递队列，在「投递记录」查看结果，并在接收端确认收到。没有配置真实凭证时，不会发送任何外部消息。

Webhook 请求附带 `Idempotency-Key: 通知任务ID`。配置签名密钥时附带 `X-SSHGuard-Signature: sha256=十六进制HMAC`，算法为 HMAC-SHA256(secret, 原始请求体)。接收方应使用恒定时间比较验证签名，按任务 ID 去重。

SMTP 使用固定 Message-ID 辅助去重、UTF-8 base64 正文。邮箱服务可能还要求授权码、正确的发件地址、SPF/DKIM 和网络出口；平台显示送达意味着服务商接受，不等于收件箱一定显示或用户已阅读。

## 密钥和目的地安全

ENCRYPTION_KEY 是 32 字节随机密钥的 64 字符十六进制表示，用于 AES-256-GCM 加密渠道配置。每条配置与渠道 ID 绑定。编辑时密钥不回显，留空保留原值；只有勾选「替换全部密钥」才会清空空白项。浏览器不会获得旧 Webhook URL、Bot Token 或 SMTP 密码。

原生向导及新 .env 生成器自动生成密钥。手工或旧 Compose 部署执行 `openssl rand -hex 32`，将结果保存到受保护的环境配置中，**只生成一次，更新时不要替换**。备份数据库时必须同时备份密钥；丢失后无法解密渠道配置。当前不支持在线密钥轮换。

所有出站连接都验证 TLS，拒绝重定向和系统 HTTP 代理，解析 DNS 后逐个检查地址并直连已验证 IP，默认阻止私网、环回与云元数据地址。使用内网 SMTP/Webhook 时，在平台环境设置 `NOTIFICATION_ALLOWED_HOSTS=smtp.internal.example,hook.internal.example`，只列准确主机名；该例外不关闭 TLS 验证。

## 检测规则

默认启用登录成功、5 分钟内同服务器同来源 5 次认证失败、离线 180 秒、采集异常持续 120 秒。新库会创建这些规则，空渠道列表使用所有启用渠道；没有渠道时仍记录告警。

- 登录与特权登录：root、Administrator，以及 Windows 域前缀下的 Administrator；不会自动推断其他具有 sudo 权限的账号。
- 失败阈值：同一服务器、来源 IP、事件时间窗口；需要按业务调整，以免扫描产生过多通知。
- 离线/采集异常：每 30 秒检查；待接入服务器不报离线。恢复时对应健康告警标记已恢复，当前不额外发送恢复通知。
- 可信 CIDR 仅忽略该规则的事件触发，不阻止事件入库，也不影响离线检测。精确填写服务器分组，空分组表示全部服务器。
- 冷却时间在数据库持久化；登录按规则+服务器+IP+用户名，失败阈值按规则+服务器+IP，健康规则按规则+服务器抑制重复。

上限：100 条规则、100 个通知渠道；每规则可指定 20 个渠道和 100 个可信 CIDR。停用渠道会终止其待投递任务，修复后重新启用并在失败记录手动重试。

## 投递可靠性

两名 worker 从数据库领取 60 秒租约，外部请求最多 20 秒；网络操作不占用数据库事务。结果按租约令牌更新，旧 worker 不能覆盖新租约结果。进程中断后过期任务可再次领取。

失败从 30 秒退避到最多 1 小时，最多尝试 8 次后进入「需要处理」。修复凭证、TLS、网络或服务商限制后手动重试。企业微信/钉钉/飞书每渠道至少间隔 3 秒，其余渠道至少 1 秒；高风险通知优先。

这是至少一次投递。外部接收成功但响应丢失时重试可能重复，消息包含稳定 Alert ID / 任务 ID 辅助判断。平台完全宕机时无法自行发送离线告警，须由独立监控探测平台 health、数据库与磁盘。

## 独立 IP 白名单

管理员在「IP 白名单」管理全局可信来源，最多 500 条，支持单个 IPv4 / IPv6 或 CIDR，保存时规范化并拒绝重复。命中后跳过登录、特权登录及失败阈值告警，事件仍正常入库；不会改变服务器离线、采集异常规则，也不会自动关闭历史告警。

单条规则的「规则 IP 白名单」继续有效，最多 100 条。两者都不控制管理控制台访问、不修改系统防火墙。新增与移除只允许管理员，要求同源请求并写操作审计。
