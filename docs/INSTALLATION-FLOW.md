# 主控安装流程

目标：用户只有一台服务器、没有域名，也能完成主控安装并接入第一台 Agent。参考 [Komari 的安装入口](https://github.com/komari-monitor/komari/blob/main/install-komari.sh)，将安装成功定义为“能够开始采集”，而非仅启动一个网页。

## 默认路径

1. 执行安装命令，确认应用端口，回车使用 8080。自动检测架构、下载校验、配置低权限服务与开机自启。
2. 打开终端给出的 `http://IP:端口/#setup=口令`，无需填写域名、反向代理或证书。
3. 创建管理员。默认 SQLite；外部数据库和连接测试放在可选的「存储设置」。初始化口令从链接读取，失败时可修改。
4. 自动登录，进入服务器管理。新增服务器后直接生成对应操作系统的安装命令。
5. 在目标机器执行命令，确认在线及采集状态，再验证一次真实登录与通知投递。

## 场景与处理

| 场景 | 行为 |
|---|---|
| 已有 Nginx / OpenResty / 宝塔 | 默认使用独立端口，保留现有服务；反代按需配置 |
| 8080 被占用 | 明确提示 `--port 8081` 等替代方式，退出后可重试 |
| 初始化链接丢失 | 管理菜单「8」或 `--setup-link`；仅交互终端显示口令 |
| 初始化时刷新页面 | 同源 sessionStorage 暂存口令，完成后清除 |
| 服务切换尚未完成 | 显示已保存状态并轮询就绪，支持重新检查；不重复创建管理员 |
| 外部数据库连接失败 | 显示可处理的错误，保留表单；拒绝覆盖非空数据库 |
| 主控 IP / NAT | Agent 命令使用管理员实际访问地址；提示确认目标机可达及端口映射 |
| 更新 / 卸载 | 更新保留原配置、身份与数据；卸载默认保留数据；管理命令直接使用已安装脚本 |

## 传输与兼容

默认原生安装显式启用 HTTP，命令中携带授权参数并持久保存到 Agent 配置。HTTP 登录、令牌、事件及下载未加密，页面和终端均说明；SHA256 仅用于完整性校验。HTTPS 继续严格校验证书、不跟随下载重定向、不自动降级。域名、HTTPS 与外部数据库不作为默认安装的前置条件。

直连模式不信任转发头，使用请求地址做同源检查和命令生成；反代继续使用显式 `PUBLIC_URL`。已有安装不自动切换协议、数据库、端口或管理员，旧 Agent 更新后才能使用新增能力。

## 验收

- `scripts/test-direct-flow.mjs`：在隔离临时目录启动真实 API / Agent，验证默认 SQLite、初始化鉴权、登录、IP 注册、心跳、事件、更新任务与重启持久化。
- Go 测试：HTTP 显式授权、IPv4 / IPv6 地址、HTTPS 证书拒绝、两种协议的 WebSocket 断线和提交后确认丢失回退。
- 原生 CI：在一次性 Linux VM 验证真实 systemd Agent 的直连安装、采集、幂等更新、平台更新及主控升级。
- 本流程包含于 v0.3.8 及后续发行包；版本标签推送后需等待完整 CI 和 Release 附件生成，固定版本下载不会包含尚未发布的源码。
