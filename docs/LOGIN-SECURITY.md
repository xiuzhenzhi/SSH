# 登录防护

管理员在「登录防护」配置验证码和管理封禁 IP。首次安装不要求域名或验证码密钥，默认不启用第三方验证码；登录错误封禁始终生效。

## 60 秒内错误 5 次，封禁 24 小时

按可信来源 IP 的滚动 60 秒窗口统计。用户名 / 密码错误和无效、过期、重用的验证码计入错误；第 5 次起返回 429，并用 `Retry-After` 表示剩余秒数。验证服务网络故障、异常响应或配置密钥错误返回 503，拒绝登录但不增加错误计数。

封禁保存于数据库，重启或多个 API 实例不会清空。24 小时到期立即允许再次尝试，不必等定时清理。并发失败按来源行锁串行计数，只记录一次封禁审计。成功登录不清除同一来源在该分钟内的失败，避免用另一个有效账号绕过计数。

封禁限制新登录，已有有效会话可继续操作。管理员可在页面解除封禁并清空该来源的本轮失败计数。SSH IP 白名单只免除 SSH 事件告警，不能绕过控制台登录防护。共用 NAT 出口的用户共用一个来源 IP，误封时由已有管理员会话解除。

仍保留每实例每分钟 60 次的认证预算，以及每账号 15 分钟 10 次密码错误的限额，作为额外限制。无效验证码先于密码校验被拒绝。

## 三种验证码，选择一种

| 服务 | 管理页填写 | 服务商设置 |
|---|---|---|
| Cloudflare Turnstile | Site Key、Secret Key | 创建网站组件，允许实际访问主机；组件 action 固定为 login |
| Google reCAPTCHA v2 | Site Key、Secret Key | 使用 v2 复选框网站密钥，允许访问主机；当前不支持 Enterprise / v3 |
| 极验第四代 | Captcha ID、Captcha Key | 创建 Web 验证应用，配置对应站点 |

只填写在对应服务商创建的真实密钥，不使用开发测试密钥发布。允许的网站主机填写域名或 IP，不含协议、端口、路径或通配符。服务商自身是否允许某个 IP / 本地主机以其后台规则为准；主控的 IP 安装不依赖这些服务。

修改配置须再次输入当前管理员密码。密钥使用现有 ENCRYPTION_KEY 加密保存，不向浏览器回显；同一服务和站点下留空保留原密钥，更换服务或站点需重新填写密钥。禁用验证码会清除该配置中的密钥，IP 封禁继续生效。

登录接口在服务端向固定 HTTPS 地址校验，不接受客户端指定校验地址或单纯的“验证成功”标记。校验主机、时效、Turnstile action、极验 HMAC / 流水号，成功令牌另外以哈希记录防重放；禁用重定向，不因供应商故障自动放行。验证码服务会处理令牌和必要的网络 / 浏览器信息，平台不会把登录密码传给它。

参考：[Turnstile 服务端验证](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)、[Google 服务端验证](https://developers.google.com/recaptcha/docs/verify)、[极验服务端 API](https://docs.geetest.com/gt4/apirefer/api/server)。

## 反代与部署

反代须正确传递真实来源 IP，否则可能将全部用户视为同一来源。默认只信任本机回环代理；跨机 / Compose 配置精确的 TRUSTED_PROXY_CIDRS，禁止信任整个互联网，使用 none 可关闭转发头信任。见 [反代说明](REVERSE-PROXY.md)。

经过 Cloudflare CDN 时，应在 Nginx 使用官方 Cloudflare 来源范围限制真实 IP 头的可信来源，再转发实际客户端地址；不要直接相信任意请求提交的 CF-Connecting-IP。Turnstile 是独立验证码接入，不会替你修改 Cloudflare WAF 或站点 DNS。

验证码组件需要从对应服务商加载脚本、框架和验证资源。新版原生 / Compose HTTPS 模板及主控 CSP 已允许这些固定来源，没有加入任意脚本域或 unsafe-eval。已有站点配置升级不会被覆盖，需合并新模板中的 CSP；保留 Origin、HTTPS 和敏感文件限制。第三方脚本被阻止时登录页会提示失败，不会自动绕过验证码。配置后保留当前管理会话，在另一个窗口人工确认正常登录，再退出旧会话。

## 本机恢复

验证码密钥错误或服务商不可用时，使用仍有效的管理员会话修改设置。所有会话均不可用时，仅有本机数据库管理权限的管理员可在备份后停服修改数据库：删除 `login_protection` 中 `id=1` 的配置即可恢复无第三方验证码模式，IP 封禁不受影响。需要解除自己的 IP 时，按 `login_guards.source_ip` 精确定位并清空该行 blocked_until，再删除对应 source_hash 的 login_failures。不要清空全部安全记录或删除业务数据库。

自动清理只分批删除过期计数与令牌哈希，删除时再次检查到期条件，防止并发刷新后的封禁状态被误删。封禁与人工解除保留在操作审计中。

## 验证范围

自动化覆盖三家校验协议、主机 / 时效 / action 拒绝、极验签名、异常响应、令牌重放、缺少验证码的直接 API 请求、密钥不回显和加密、5 次封禁、滚动窗口、并发及过期解除。协议测试使用隔离响应；没有用户的服务商生产密钥，不将其描述为已通过三家真实站点的人机验证验收。
