# 告警与通知

## 配置通知渠道

进入「通知渠道」，新增渠道并保存，点击「发送测试」。在「投递记录」查看结果。

| 渠道 | 需要填写 |
|---|---|
| 企业微信 | 群机器人 HTTPS Webhook |
| 钉钉 | HTTPS Webhook，可选加签密钥 |
| 飞书 | HTTPS Webhook，可选签名密钥 |
| Telegram | Bot Token、Chat ID |
| SMTP | 主机、端口、TLS 模式、发件人、收件人及认证信息 |
| Webhook | HTTPS 地址，可选签名密钥 |

SMTP 支持隐式 TLS 和 STARTTLS。内网 SMTP / Webhook 需在 `NOTIFICATION_ALLOWED_HOSTS` 中加入准确主机名。

## 检测规则

在「检测规则」选择通知渠道、服务器分组和冷却时间。

| 默认规则 | 触发条件 |
|---|---|
| 登录成功 | 收到成功登录事件 |
| 认证失败 | 5 分钟内，同服务器同来源失败 5 次 |
| 服务器离线 | 180 秒未收到心跳 |
| 采集异常 | 异常持续 120 秒 |

每条规则最多选择 20 个渠道，最多配置 100 条规则和 100 个渠道。服务器恢复后，健康告警标记为已恢复。

## 确认告警

「告警中心」支持单条确认、勾选批量确认和「全部确认」。全部确认跨分页生效，已确认和已恢复记录会跳过。

管理员和操作员可确认，查看者只读。确认记录可在「操作审计」查询。

## IP 白名单

在「IP 白名单」添加 IP 或 CIDR，最多 500 条。命中后不触发 SSH 登录告警，事件仍会保存。

单条规则也可配置自己的白名单，最多 100 条。白名单不影响控制台登录封禁。

## 投递失败

系统最多重试 8 次。检查凭证、TLS 和网络后，在失败记录中点击重试。停用渠道会终止其待投递任务。

自定义 Webhook 请求带有 `Idempotency-Key`；启用签名时，`X-SSHGuard-Signature` 为原始请求体的 HMAC-SHA256。接收端可按任务 ID 去重。

密钥备份见 [运维手册](../deployment/OPERATIONS.md#账号与密钥)。
