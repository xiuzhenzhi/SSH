# 数据库与数据保留

管理员在控制台的「数据库」页面查看数据库类型和占用，并设置 SSH 事件、告警与投递记录、操作审计的保留天数。

## 存储占用与维护

SQLite 显示主数据库文件、WAL 写入日志及 SHM 共享内存文件的合计大小。PostgreSQL / MySQL 显示当前数据库的占用；权限不足或暂时无法查询时显示「暂不可用」。页面不会暴露数据库密码或连接串。

SQLite 可点击「回收空间」，核对确认框后开始后台维护。流程为 checkpoint → VACUUM → checkpoint，回收删除记录后留下的空闲空间，不删除仍存在的记录。维护期间查询和 Agent 上报可能暂时变慢；重复维护请求会被拒绝。

任务最长运行 5 分钟，主控关闭时取消任务。执行时按钮显示「维护中…」，完成后显示短暂提示，不保留占用变化提示。可以离开页面，稍后返回查看当前状态，历史结果在操作审计中查看；任务状态随主控进程保存，重启后通过占用和操作审计核对结果。PostgreSQL 执行 VACUUM + ANALYZE，清理无效行并更新统计，主要使表内空间可复用；不执行会长时间独占表的 VACUUM FULL。MySQL 执行 OPTIMIZE TABLE，检查每张表的返回状态，整理表和索引空间；操作可能重建表、持有表锁并需要临时磁盘空间。两者仅操作 SSHGuard 自身的固定表清单，不扫描或优化其他应用的表。数据库账号需要对应维护权限。外部数据库维护不是整体事务，失败时可能已有部分表完成。连接取消后服务器端操作可能仍在结束中，请先检查数据库状态再重试。

## 保留天数

- 范围为 0–3650 天，0 表示永久保留。
- 默认沿用安装配置：SSH 事件 30 天、告警 90 天、操作审计 180 天。
- 网页保存的策略写入数据库，优先于安装时的环境变量，重启后仍有效。
- 自动清理每 10 分钟运行一次，每类最多删除 1,000 条过期记录，避免长事务阻塞服务。
- 未发送、正在发送和发送失败的通知及关联告警继续保留，避免清理过程抹去投递失败的证据。
- 缩短保留期限可能永久删除过期数据，保存前会要求确认；空间回收与过期记录删除是两个独立操作。

当前数据库连接在首次初始化时配置。更换数据库需先备份并迁移数据，参见[备份与恢复](../deployment/OPERATIONS.md)。
